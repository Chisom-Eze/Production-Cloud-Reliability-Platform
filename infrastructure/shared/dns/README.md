# Shared Authoritative DNS

`shared/dns` is an independent Terraform deployment root at `infrastructure/shared/dns`. It owns only the public Route53 hosted zone for `chisomeze.online`, shared across environments. The domain input intentionally accepts only `chisomeze.online`; the AWS provider region is `us-east-1`, consistent with the other shared roots.

## Ownership And State

The root uses partial S3 backend configuration with the existing state bucket `pcrp-terraform-state-us-east-1`, encryption, native S3 locking (`use_lockfile = true`), and this independent state key:

```text
shared/dns/terraform.tfstate
```

Bootstrap owns backend infrastructure and deployment IAM. This root owns the hosted zone; development and other environment roots must not declare another copy of it. Development teardown must leave this root and its state intact.

Route53 automatically creates the zone's SOA and NS records. This root declares no `aws_route53_record` resources. Application records, ACM validation records, ALB aliases, and environment-specific DNS records remain under their separate environment ownership. The `hosted_zone_id` output provides the identifier for that later work.

## Permanent Workflow Support

Select `shared/dns` in the existing manual Terraform Development Plan workflow. It maps to this root, the state key above, and artifact slug `dns`. Review the resulting binary plan before dispatching Terraform Development Apply with the exact Plan run ID, run attempt, selected root, and required confirmation.

The existing Plan/Apply OIDC identities and GitHub environments remain in use. Apply validates the exact Plan attempt, checks out its source SHA, verifies artifact metadata and the binary plan digest, and applies only that verified plan.

The permanent workflows initialize with `-lockfile=readonly`. Before the first authenticated Plan run, generate and review this root's `.terraform.lock.hcl` using backend-disabled initialization, then commit it. The lockfile is not generated by this source change. `scripts/terraform-quality.sh` includes this root for formatting, backend-disabled initialization, validation, TFLint, and infrastructure-wide Trivy scans.

## Namecheap Delegation

After the first successful apply:

1. Read the `name_servers` output and copy all four Route53 nameservers.
2. Review any existing Namecheap-hosted DNS records before switching authority; this zone initially has only its automatic SOA and NS records.
3. In Namecheap, configure the domain's nameservers as **Custom DNS** using those four Route53 nameservers.
4. Allow delegation to propagate and verify the parent delegation and authoritative NS/SOA responses, for example with `dig +trace chisomeze.online NS` and `dig @<one-route53-nameserver> chisomeze.online SOA`.
5. Continue development ACM validation and application DNS work only after delegation resolves to the intended Route53 zone.

Namecheap configuration is a manual operator action and is not managed by this root.

## Deliberate Protection And Cost

`lifecycle.prevent_destroy = true` blocks Terraform destruction or replacement of the hosted zone while its resource declaration remains present. Retain the declaration and remote state; removing the resource block also removes that lifecycle protection. Any future retirement requires a deliberate review of delegation, records, consumers, and state ownership.

The hosted zone incurs its own ongoing charge even when development runtime infrastructure is destroyed. A separate retained root preserves shared authoritative DNS through those development lifecycle changes. Environment records, certificate validation, ALB aliases, and registrar automation are deliberately excluded from this deployment unit.
